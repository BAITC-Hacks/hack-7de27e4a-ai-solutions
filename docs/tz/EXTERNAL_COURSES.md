# External Learning Layer

**Внешние курсы для навыков, которые каталог компании не закрывает**

_ТЗ на продвинутую фичу - 2 из 2_

> Вторая половина той же дыры: там, где ментор не поможет, потому что навык технический. Документ описывает, как добавить внешние курсы, не разрушив главное - доверие к цифрам движка.

## 1. Зачем это нужно

Сейчас, если каталог компании не может дотянуть навык до требования грейда, система про это просто молчит. Масштаб проблемы измерен на реальных данных:

| Что померили | Значение |
|---|---|
| У скольких сотрудников есть разрыв, непокрываемый каталогом | 183 из 190 с целью |
| У скольких непокрытый разрыв КРИТИЧЕН, то есть блокирует повышение | 125 |
| Из них блокер - только hard-навыки (ментор тут не поможет) | 78 |
| Ещё и hard, и soft одновременно | 10 |
| Различных навыков без покрытия каталогом | 59 из 60 |

> **88 человек имеют технический блокер повышения, которому в каталоге компании не соответствует ни одна активность. Ментор тут бесполезен: SQL или A/B-тестирование перенимают не в разговоре. Нужен курс - и его нет внутри.**

### Что это даёт HR

Экран HR уже умеет показывать, каких активностей не хватает. Сейчас это констатация. С внешними курсами она превращается в план: вот чем закрыть прямо сейчас и вот что имеет смысл поставить в бюджет следующего цикла, с указанием, скольких людей это разблокирует.

---

## 2. Железное правило: вне скоринга

> **Внешние курсы НЕ участвуют в ранжировании, НЕ попадают в top-3 и НЕ влияют на readiness. Это не осторожность, это защита главного актива проекта.**

Вся достоверность движка держится на одном: правило роста навыка задано датасетом. У каждой активности прописаны gain и max_level, и мы этим обоснованно хвалимся. У курса с внешней платформы таких данных нет и взять их неоткуда.

Если приписать курсу «плюс один к System Design», мы своими руками сделаем ровно то, за что критикуем однофакторный baseline - выдумаем число. На защите прозвучит вопрос «откуда цифра», и ответить будет нечем. Одна выдуманная цифра обесценивает весь Trust Center.

Поэтому курсы живут отдельным слоем с явной подписью: внешний источник, эффект не подтверждён данными компании. Это честнее и защищается железно, а интеграция с чужим API - нет.

## 3. Модель данных

```
data/external_courses.json

course
  id, title, provider, url
  languages: [ru | kk | en]
  durationHours, free: boolean
  developsSkillIds: [SK_...]      <- СПИСОК ID, без gain и без max_level
  suitableFrom, suitableTo        <- редакторская оценка диапазона уровней,
                                     в расчётах НЕ используется
  source: "external"
```

Zod-схема обязательна, как и для остальных файлов. Каждый developsSkillIds проверяется на существование в skills.json: курс со ссылкой на несуществующий навык отклоняется при загрузке.

### Откуда берём каталог

- Курируемый офлайновый список на 25-35 курсов, покрывающий топ непокрытых навыков.
- Никаких обращений к внешним API во время работы. Причины две: сеть на демо - лишняя точка отказа, и всё равно ни один провайдер не отдаст нам gain в нашей шкале.
- Приоритет по данным: Communication (87 человек), Mentoring (64), SQL (57), Stakeholder Management (45), Leadership (36), Problem Solving (31), Product Knowledge (31), CRM Systems (28), Critical Thinking (28), A/B Testing (28), Teamwork (27), Product Analytics (27).

## 4. Отбор и показ

### Порядок отбора - чистая детерминированная функция

- Вход: сотрудник и набор непокрытых разрывов, посчитанных движком.
- Выход: до трёх курсов на навык.
- Ранжирование: совпадение по навыку, попадание текущего уровня в диапазон пригодности, совпадение с preferred_language сотрудника, бесплатность, меньшая длительность.
- Стабильный tie-break по id курса - как и везде в проекте.

Язык здесь не косметика: русский предпочитают 100 человек, казахский 89, английский 11. Курс на языке, которым человек не пользуется, рекомендацией не является.

### Где показывается

| Экран | Когда показывать | Что показывать |
|---|---|---|
| Сотрудник | Только если есть разрыв, который каталог не закрывает | Блок под рекомендациями, заголовок прямо говорит, что внутри компании такого нет |
| HR | Рядом со списком дыр каталога | Чем закрыть снаружи сейчас и что стоит закупить, со счётчиком разблокируемых людей |

> **Блок не показывается, когда каталог разрыв закрывает. Иначе внешние курсы начнут конкурировать с собственными программами компании - а это прямо противоречит смыслу продукта и интересам заказчика.**

## 5. Безопасность и честность

- Только https-ссылки, домены из allowlist в коде.
- Внешние ссылки открываются с rel=noopener noreferrer.
- Тексты курсов - данные, а не инструкции; в LLM они не передаются.
- Нигде не показывается числовой прирост навыка от внешнего курса.
- В карточке курса обязательна подпись про внешний источник и неподтверждённый эффект.

## 6. Порядок реализации

| Фаза | Что делаем | Оценка |
|---|---|---|
| 1 | Схема, файл каталога, валидация ссылок на навыки | 30-40 мин |
| 2 | Функция отбора и тесты | 30 мин |
| 3 | Блок у сотрудника и блок у HR | 30-40 мин |

Итого около полутора часов. Это самая дешёвая из обсуждавшихся фич и единственная, которая закрывает 88 человек сразу.

## 7. Критерии приёмки

| Проверка | Ожидаемый результат |
|---|---|
| Внешний курс и обычная активность конкурируют | Курс не появляется в top-3 никогда |
| Добавили курсы в каталог | readiness и прогресс навыков не изменились |
| Разрыв закрывается активностью компании | Блок внешних курсов не показывается |
| Разрыв каталогом не закрывается | Блок показывается с подписью про внешний источник |
| Сотрудник с preferred_language kk | Курсы на казахском выше в списке |
| Курс ссылается на несуществующий навык | Отклоняется схемой при загрузке |
| Повторный вызов отбора | Тот же порядок курсов |
| Экран HR | Видно, скольких людей разблокирует закупка каждого направления |
| Карточка курса | Нет ни одной цифры прироста навыка |

## 8. Обязательные тесты

- внешний курс не попадает в ранжированный top-3;
- наличие курсов не меняет readiness и effective skills;
- блок скрыт, когда каталог компании разрыв закрывает;
- отбор детерминирован при одинаковом входе;
- курс с несуществующим skill_id отклоняется схемой;
- предпочитаемый язык поднимает соответствующие курсы выше;
- в выдаче отсутствует любое поле с числовым приростом.

## 9. Что написать в README

- Что каталог курируемый и офлайновый, без обращений к внешним API.
- Цифру 88: столько человек имеют технический блокер повышения без активности внутри компании.

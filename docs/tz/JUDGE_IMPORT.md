# Загрузка проверочных профилей

**Обязательный пункт ТЗ, который сейчас не работает**

_ТЗ для Codex - приоритет 1_

> На защите жюри загружает свои профили. Сегодня наш загрузчик их с высокой вероятностью отвергнет. Движок при этом полностью исправен - потерять кейс можно на форме загрузки.

> **Это не улучшение и не фича. Это обязательное требование ТЗ, которое сейчас сломано. Приоритет выше геймификации, чата, внешних курсов и агентного слоя вместе взятых.**

## 1. Что требует ТЗ

Дословно из раздела must-have: «Решение должно загружать дополнительные профили и историю в формате датасета: на защите жюри загружает проверочные профили».

И из README стартового кита организаторов: evaluation uses additional employee profiles and history records in the same format, your solution must be able to load them.

Ключевое слово - ДОПОЛНИТЕЛЬНЫЕ. Жюри почти наверняка принесёт один-два файла: профили и записи истории. Полный комплект из четырёх файлов оно приносить не обязано, и по смыслу формулировки - не будет.

## 2. Что сломано сейчас

| Проблема | Что происходит на защите |
|---|---|
| Принимаются только четыре точных имени файлов | Файл judge_profiles.json отбрасывается с текстом «Неизвестный файл» |
| Чтение обращается ко всем четырём файлам без проверки наличия | Набор из одного-двух файлов падает с общей ошибкой «Не удалось прочитать файлы» |
| Импорт всегда заменяет набор целиком | Даже при удачной загрузке проверочные профили вытесняют исходные 200, а не добавляются |

> **Сложите три пункта: жюри приносит файл со своим именем, мы отвечаем «неизвестный файл». Обязательный пункт провален при полностью исправном движке.**

---

## 3. Определение типа по содержимому

Имя файла перестаёт быть источником правды. Тип определяется по структуре.

| Признак | Тип |
|---|---|
| CSV с колонками record_id, employee_id, event_id | история участия |
| JSON с ключом employees, либо массив объектов с полем employee_id | профили |
| JSON с ключом events, либо массив объектов с полем event_id | события |
| JSON с ключами skills и role_profiles | навыки и требования |

> **Если тип определить не удалось или он неоднозначен - НЕ угадывать. Показать файл и попросить выбрать тип вручную. Молчаливая догадка на защите хуже честного вопроса.**

## 4. Два режима импорта

| Режим | Когда по умолчанию | Что делает |
|---|---|---|
| Заменить | Набор ещё не загружен | Полная замена, текущее поведение |
| Дополнить | Набор уже загружен | Добавляет профили и историю к существующим |

### Правила слияния

- Новый employee_id - добавляется. Существующий - заменяется, и это отражается в сводке.
- События и навыки - так же, по своим id.
- Строки истории сливаются по record_id.
- Строка со ссылкой на неизвестного сотрудника или событие отклоняется с номером строки.
- После слияния ссылочная целостность перепроверяется ПОЛНОСТЬЮ.
- Если слияние ломает целостность - откат целиком. Половинчатого состояния быть не должно.

### Журнал сессии

Если после слияния запись журнала ссылается на исчезнувшего сотрудника или событие, она удаляется, и об этом сообщается в сводке. Молча ломать журнал нельзя: пользователь должен понимать, почему его отмеченные активности исчезли.

---

## 5. Частичные наборы и терпимость к формату

- Принимается от одного до четырёх файлов.
- Недостающие части берутся из уже загруженного набора.
- Если набора нет и не хватает навыков или событий - ошибка называет, чего именно не хватает.
- Терпимость: UTF-8 BOM, переводы строк CRLF, пробелы вокруг значений.
- Лимит 10 МБ на файл сохраняется.
- Любая ошибка называет файл, путь или номер строки и причину - это уже записано в DoD потока A.

## 6. Сводка после импорта

Обязательна. Это и защита от тихих потерь, и главный момент демонстрации.

```
Импорт завершён

  добавлено профилей:        3
  обновлено профилей:        0
  добавлено записей истории: 47
  отклонено строк:           2  (строка 18: неизвестный event_id EV_099;
                                 строка 23: неизвестный employee_id E9001)
  удалено записей журнала:   0

  [ перейти к добавленным профилям ]
```

> **Кнопка «перейти к добавленным профилям» открывает первый новый профиль. На защите это выглядит так: жюри загружает файл, один клик - и на экране их профиль с рекомендацией и обоснованием. Ради этого момента всё и делается.**

## 7. Фикстуры для репетиции

Каталог fixtures/judge/ с наборами, эмулирующими поведение жюри. Тесты грузят именно их, а команда прогоняет их руками перед сдачей.

| Фикстура | Что проверяет |
|---|---|
| Только профили, один файл | Частичный набор проходит |
| Профили плюс история, два файла | Основной ожидаемый сценарий жюри |
| Файл с нестандартным именем | Определение типа по содержимому |
| Профиль с межролевой карьерной целью | Target берётся из цели, а не из следующего грейда |
| Профиль без истории вообще | Нейтральный prior, система не падает |
| Профиль-ловушка для однофакторного правила | Побеждает критичный разрыв, а не минимальный навык |
| История со строкой на неизвестное событие | Отклонение с номером строки, остальное грузится |

## 8. Критерии приёмки

| Проверка | Ожидаемый результат |
|---|---|
| Загружен один файл с профилями | Импорт проходит, остальное берётся из текущего набора |
| Файл назван judge_profiles.json | Распознан как профили по содержимому |
| Режим «дополнить» на загруженном наборе | Стало 203 профиля, исходные 200 на месте |
| Строка истории с неизвестным employee_id | Отклонена с номером строки, импорт продолжен |
| Слияние ломает ссылочную целостность | Откат целиком, набор не изменился |
| Файл в UTF-8 с BOM и CRLF | Импортируется без ошибок |
| Файл непонятного типа | Запрос выбрать тип вручную, а не догадка |
| После импорта | Сводка с числами и кнопка перехода к новым профилям |
| Клик по кнопке перехода | Открыт первый добавленный профиль с рекомендацией |
| Запись журнала указывает на исчезнувшего сотрудника | Удалена, сообщено в сводке |

## 9. Порядок реализации

| Фаза | Что делаем | Оценка |
|---|---|---|
| 1 | Детектор типа и приём от одного до четырёх файлов | 1 ч |
| 2 | Режим «дополнить», атомарная валидация, чистка журнала | 1-1.5 ч |
| 3 | Сводка и переход к добавленным профилям | 40 мин |
| 4 | Фикстуры и тесты, ручная репетиция трижды | 1 ч |

Итого 3.5-4 часа. Самая дешёвая страховка от самого дорогого провала на защите.

## 10. Обязательные тесты

- набор из одного файла проходит;
- файл с произвольным именем распознан по содержимому;
- неоднозначный файл не угадывается, а запрашивает выбор;
- режим «дополнить» добавляет профили к существующим;
- существующий employee_id заменяется и попадает в сводку как обновлённый;
- строка с неизвестным employee_id отклонена с номером строки;
- слияние, ломающее целостность, откатывается целиком;
- BOM и CRLF не мешают разбору;
- запись журнала на исчезнувшего сотрудника удаляется и попадает в сводку;
- все шесть фикстур из fixtures/judge загружаются и дают рекомендацию.

СЕЙЧАС СЛОМАНО ТРИ ВЕЩИ. Первое: загрузчик принимает только файлы с точными именами employees.json, events.json, skills.json, activity_history.csv, любое другое имя отбрасывается как 'Неизвестный файл'. ТЕРПИМОСТЬ К ФОРМАТУ: UTF-8 BOM, переводы строк CRLF, пробелы вокруг значений. Лимит 10 МБ на файл сохраняется. Ошибки всегда называют файл, путь или номер строки и причину.
